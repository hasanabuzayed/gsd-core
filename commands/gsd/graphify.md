## MVP-Mode Node Rendering

**MVP-mode rendering.** When a phase has `**Mode:** mvp` in ROADMAP.md, show its graph node with two distinct visual signals. The mode is resolved via `gsd-tools query roadmap.get-phase --pick mode`:

1. **Distinct fill color.** Use `#22c55e` (green) for MVP-mode phase nodes. Standard phases keep the default fill color. Two-channel signaling (color + label) handles color-blind and grayscale renders.
2. **`MVP` label suffix.** Append ` (MVP)` to the node's label text. For example, a phase originally labeled `Phase 1: User Auth` shows as `Phase 1: User Auth (MVP)`.

Use both signals together. Never use just one. Per PRD Q5 decision, the goal is unambiguous visual distinction in any render context.

When the phase mode is null/absent, show the standard color and label. This does not change the behavior for non-MVP phases.

## Anti-Patterns

1. DO NOT spawn an agent for any operation. The build, query, status, and diff operations all run inline. When the agent exits, sub-agent isolation stops background bash. This previously truncated graphify builds mid-write and left only the cache populated (#3166).
2. DO NOT pass `run_in_background: true` for the build chain. The operation is fast and must complete in the foreground.
3. DO NOT change graph files directly. Always use `graphify update .` and the snapshot CLI.
4. DO NOT skip the config gate check.
5. DO NOT use `gsd-tools config get-value` for the config gate. It exits on missing keys.
